# Учёт расходов

Небольшая страница для записи личных трат. Работает в браузере на компьютере и телефоне; данные остаются в localStorage этого браузера.

## Что умеет

1. **Добавление траты** — сумма в целых тенге, категория, дата и необязательный комментарий. [Спецификация](specs/001-expense-tracking.md).
2. **Итоги по категориям** — общая сумма расходов и разбивка по категориям. [Спецификация](specs/002-budget-by-category.md).
3. **Быстрые шаблоны трат** — можно сохранить сумму, категорию и комментарий под названием, затем подставить их в форму и проверить перед добавлением. [Спецификация](specs/003-quick-templates.md).

## Как открыть и проверить

Откройте `index.html` двойным щелчком в браузере. Внешние зависимости и установка пакетов не нужны.

1. Добавьте траты 5 000, 2 500 и 12 000 ₸ с датами текущего месяца — итог должен стать **19 500 ₸**.
2. Добавьте запись за прошлый месяц — она появится в истории, но текущий итог не изменится.
3. Обновите страницу клавишей F5 — записи должны сохраниться.
4. Попробуйте отправить пустую сумму, ноль или дробное значение — появится подсказка, запись не добавится.
5. Сохраните шаблон «Обед» с суммой 5 000 ₸ и категорией «Еда», выберите его и убедитесь, что форма заполнилась, а трата не добавилась до нажатия «Добавить трату».
6. Попробуйте сохранить шаблон с пустой суммой — он не должен появиться. Проверьте отображение суммы 1 250 000 ₸.
7. Обновите страницу и убедитесь, что шаблон остался. Удалите его и проверьте, что сохранённая трата осталась в истории.
8. Откройте страницу в окне шириной 375px и проверьте, что форма, шаблоны и история помещаются без горизонтальной прокрутки.

## Правила для агента

Все правила проекта описаны в файле [AGENTS.md](AGENTS.md).

**Ошибка, которая возникла в процессе:** при попытке выполнить команду `git status` агент получал сообщение «git не распознан». При этом в терминале пользователя команда работала. Агент останавливался и отказывался продолжать работу из-за правила «при ошибке Git остановиться».

**Правило, которое мы добавили:** «Если агент не видит Git в своей песочнице, но в терминале пользователя `git status` работает, он должен сообщить об этом и продолжить работу по спецификации, не останавливаясь».

## Отчёт

**Правило, которое сработало сразу:** правило о формате денег. Все суммы отображались как `15 000 ₸` с пробелами и знаком тенге, пустые и неверные суммы не сохранялись, `NaN` не появлялся.

**Правило, которое не сработало:** правило «при ошибке Git остановиться». Агент запускается в изолированной среде (песочнице), где Git не был добавлен в PATH. Из-за этого он видел ошибку даже тогда, когда в обычном терминале всё работало, и отказывался продолжать.

**Как мы его переписали:** мы добавили уточнение в `AGENTS.md`: если ошибка Git возникает только в песочнице агента, а в терминале пользователя команда доступна, агент должен сообщить об этом и продолжить работу по спецификации. Это правило позволило завершить реализацию функции без остановки.
